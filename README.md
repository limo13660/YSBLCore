## YSBLCore / Mihomo Meta baseline

YSBLCore tracks the official [MetaCubeX/mihomo `Meta` branch](https://github.com/MetaCubeX/mihomo/tree/Meta).
The current baseline is `v1.19.33` (official Mihomo commit `3f27ef39f8c96bbfbc8b0b9bb10f5c9ef60149d8`).
Upstream protocol implementations, including Sudoku, are used directly. The
YSBLCore-specific changes are limited to the embedding hooks and protocol
extensions that were already part of the client baseline; they must be kept
when syncing a newer official Meta release.

The Flutter client owns listener and TUN lifecycle. Core configuration updates
therefore update routing, proxies and rules in place; they do not recreate an
active TUN interface. `StopListener` is reserved for an explicit VPN stop or
shutdown. Existing YSBLCore protocol extensions remain enabled, including
Mieru, Naive, Brook and Juicity, and must not be removed when syncing upstream changes.

## Features

- Local HTTP/HTTPS/SOCKS server with authentication support
- VMess, VLESS, Shadowsocks, Trojan, Snell, TUIC, Hysteria, Sudoku, Naive, Brook, and Juicity protocol support
- Built-in DNS server that aims to minimize DNS pollution attack impact, supports DoH/DoT upstream and fake IP.
- Rules based off domains, GEOIP, IPCIDR or Process to forward packets to different nodes
- Remote groups allow users to implement powerful rules. Supports automatic fallback, load balancing or auto select node
  based off latency
- Remote providers, allowing users to get node lists remotely instead of hard-coding in config
- Netfilter TCP redirecting. Deploy Mihomo on your Internet gateway with `iptables`.
- Comprehensive HTTP RESTful API controller

## For development

Requirements:
[Go 1.20 or newer](https://go.dev/dl/)

Build mihomo:

```shell
git clone https://github.com/MetaCubeX/mihomo.git
cd mihomo && go mod download
go build
```

Set go proxy if a connection to GitHub is not possible:

```shell
go env -w GOPROXY=https://goproxy.io,direct
```

Build with gvisor tun stack:

```shell
go build -tags with_gvisor
```

Build with Naive outbound support and dynamic Cronet loading:

```shell
CGO_ENABLED=0 go build -tags 'with_naive with_purego'
```

Naive requires a platform-matching Cronet shared library at runtime. Place `libcronet.so`, `libcronet.dylib`, or `libcronet.dll` next to the executable or in the platform library search path. Builds without `with_naive` still recognize Naive configuration and return an explicit unsupported-build error.

### IPTABLES configuration

Work on Linux OS which supported `iptables`

```yaml
# Enable the TPROXY listener
tproxy-port: 9898

iptables:
  enable: true # default is false
  inbound-interface: eth0 # detect the inbound interface, default is 'lo'
```
